# 发现页电影与剧集目录聚合

第一组为“电影 / 剧集”多选 chips，支持同时显示两种内容，也可全部取消。第二组为“全部 / 热门 / 最新”单选 chips，位于内容类型之后。首次无历史选择时默认电影、全部；旧深链接上的明确选择会保留。其他内容类型继续使用原目录。

## 候选范围

- 全部：合并下面热门与最新两组来源，按同样的身份规则去重；使用 IMDb 分数降序、英文名同分排序。
- 热门：当前账号已安装 Cinemeta 的 `top` 和 TMDB Addon 的 `tmdb.top`。
- 最新：扫描已安装插件的所选电影/剧集目录，纳入 Cinemeta `year`、TMDB `tmdb.latest` 和明确标为 Latest / New Releases / 最新等的电影/剧集目录。Cinemeta 读取当年和前一年，避免跨年时只剩少量新片。
- 不纳入个人历史、待看、推荐、趋势、任意年份筛选或系列合集。没有声明“最新”的插件不能凭空提供最新目录。
- 每个目录最多读取 200 条、10 页；单页最多等待 12 秒，单目录收集约 35 秒后停止继续请求。先读取插件的分页响应以核对返回数量和新影片身份，再通过原 Stremio Core 的 LoadNextPage 请求和序列化；不能把 skip 直接放入 Load，因为 Core 会删除该参数。此校验也能区分翻页中的旧 Ready 数据与真正的空页。最终影片由 Core 序列化，保留影片路由、观看状态和片库状态。收集过程不写插件配置。
- 这不是整个互联网电影数据库的全局排名。首批目录返回即显示已取得的影片，后续分页到达时继续合并、去重和排序；评分等资料核对完成后更新最终顺序。合并结果最多展示 300 部。已有完整列表在后台刷新时保留，不退回空白或较少的首批结果。

## 身份、排序与资料

先区分电影与剧集，防止两种内容错误合并。同类内容优先通过 IMDb 编号或可信 IMDb title 链接跨插件合并；没有 IMDb 身份的保留明确的 TMDB 编号，其他编号按来源隔离。不会用同名影片做猜测合并。合并时保留观看和片库状态；优先保留 IMDb 身份条目的原始详情链接。

全部和热门按 IMDb 分数降序，再按英文名称字母序，不忽略开头的 The / A。IMDb 分数与英文标题通过已安装 Cinemeta 的目录或 meta 接口核对。部分 TMDB 插件将 TMDB 分数填进 IMDb 字段，因此不能直接使用这些值。无法取得 IMDb 分数的放最后。资料请求并发最多 6 个，单个 6 秒超时，一轮资料核对最多等待 15 秒，内存缓存最多 600 条、15 分钟，不存入账号。

最新按完整发行日期降序，同日按英文名称排列，未来发行的排除；日期未知的放最后。年份不伪造为 1 月 1 日。优先采用 Cinemeta 的日期，否则保留原插件日期。这不是“已发行数字高清版”的保证，也不代表一定有可播放片源。

类型 chips 在聚合候选中前端筛选，不重新读取目录。观看/片库状态变化后静默重新读取 Core 缓存与资料缓存，保持原显示内容直到新结果可用，不将旧请求结果写入新选择。离开页面或切换目录会取消本轮收集。

插件失败时保留其他已取得的结果，失败和资料缺失状态仍由内部逻辑记录；发现页面不显示额外的资料核实、列表加载提示或重试按钮。用户账号、插件安装清单和观看记录不因收集过程改变。

## 验证

聚合单元测试覆盖目录识别、跨年、跨身份去重、IMDb 分数真实性、同分英文顺序、完整日期和未来日期、分页、重复页、插件失败与取消。真实浏览器的收据与发布 SHA、Worker 版本另行记录；构建通过不等于账号插件的功能验收。

## 筛选状态

内容类型、榜单与题材使用 `stremio-discover-filters-v1` 保存于本站本地存储；规范化后的分享链接同时带 `types`、`catalog`、`genre`。每次操作仅修改对应字段，其他字段原样保留。空 `genre=` 明确表示全部题材，避免旧保存值重新覆盖。即便某个题材在新类型里尚无结果，也保留其选中状态，不自动重置。隐藏已观看、隐藏中日韩印及东南亚继续使用各自已发布的布尔存储键，彼此独立。刷新页面、离开再回来后仍恢复选择。

混合选择通过原 Core 分别读取 movie / series 路径，首个电影目录之后尽早读取首个剧集目录。评分、日期、双语资料、详情链接和观看状态仍按各自内容身份处理。每个来源的读取上限与最终 300 条上限不变；“全部”指已安装来源中的热门和最新候选合集，不代表互联网所有影片。
